# 电话号码锚定实验

基于附带的 `classroom-quiz.zip` 改写，沿用它的静态网页和三条 MQTT 实时中继线路，不需要 Microsoft 或 ChatGPT 登录。

教师页面：https://ty-workshop.github.io/classroom-anchor-experiment/#host

学生链接和二维码在教师页面中生成。不要把教师页面链接当作学生问卷链接。

学生只看到两页，没有问卷标题：

1. 用常用电话号码最后两位填写两位被试编号。明确只收末两位，不收姓名或完整电话号码。
2. 阅读教师编辑的产品名称和介绍，填写最高愿付价格，单位人民币元。无需先回答“是否愿以尾号价格购买”。

教师打开网站（或 `#host`），可以修改两道问题、产品名称和长篇产品介绍，获取学生二维码，实时查看每组人数与平均最高愿付价格。两组默认 00–49 / 50–99；三组默认 00–32 / 33–66 / 67–99，均可调整分界。切换分组立即重新计算已经收集的原始回答。

投影按钮只显示结果及两组／三组切换；原始回答和题目编辑不出现在投影模式。0 元计入平均值，没有回答的组显示空值。重复尾号不会合并：用随机浏览器编号防止同一次提交因重试而重复计数。学生收到教师确认后才显示“提交成功”。

## 上课

1. 在自己的常用浏览器打开教师页面，改产品介绍并保存。
2. 等“课堂已连接”，用手机扫码测试两页和提交。若连接失败，可展开“连接线路”换线路，再扫码。
3. 测试完点“新一轮实验”，再给学生二维码。学生不需要登录。
4. 保持教师页面打开、电脑联网且不休眠。点击“投影结果”，按需切换两组或三组。收集完成后可暂停收集。
5. 下载本轮 CSV，或全部历史轮次 CSV。新一轮不会删除上一轮回答，上一轮存入本机历史。

学生链接包含课堂房间信息，可复制给学生。老师换线路后须重新给学生链接或二维码。教师刷新可恢复本轮与历史；学生刷新也能恢复已确认回答或重试未确认提交。教师端在同一浏览器只能开启一份。

## 存储与网络

与原 App 相同，教师端承担课堂实时接收与统计，不是持续运行的云端数据库。数据保存在教师浏览器本机，换电脑、无痕模式退出或清除浏览器数据后不能恢复，课后请导出。修改题目时若已有回答，会询问是否保存本轮并开始新一轮，避免把不同产品混算。

程序和依赖公开托管，学生回答不写入网站仓库。中继传输用 AES-GCM 加密；课堂密钥包含在学生链接中，因此只向本班分享链接。两位尾号不能单独识别完整电话，但与愿付价格一样属于本次收集的数据，CSV 保留该值。没有收集姓名、完整电话或账号。

免费公共 MQTT 服务不保证可用性。香港学生的实际校园／手机网络需课前测试；学校网络可能限制 WebSocket。提供三条线路供切换，程序本身不依赖 ChatGPT 网站。

## 文件

- `index.html`、`style.css`、`app.js`：问卷和教师端。
- `vendor/`：随网页一起托管的 MQTT.js 5.10.1 和 QRCode.js 1.0.0，避免学生打开时再请求第三方脚本 CDN。
- `source-original/`：原始附件备份，不发布。

可部署到任何支持 HTTPS 的静态网站托管服务。本机开发需要 localhost 服务器（直接双击文件没有 HTTPS 加密运行环境）。

这是一种两道问题的课堂锚定演示；它省略了原研究的先回答“是否愿按锚价格购买”等流程。电话尾号分组不等于随机分派，组均值差异用于课堂讨论，不应视为单次实验已经证明因果效应。
